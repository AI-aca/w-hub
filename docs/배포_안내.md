# W-HUB 배포 안내 (1단계: 새 Supabase 프로젝트)

기준: docs/계획서.md(프로젝트 문서 31). **W-HUB 는 새 Supabase 프로젝트 하나만 씁니다.**
기존 프로젝트(School Record·2027SCI·YSIE)와 기존 사이트 7개는 그대로 돌아가고, 아무것도 바꾸지 않습니다.

## 0. 원장님이 하실 일 — 새 Supabase 프로젝트 만들기

1. supabase.com → New project. 이름 `w-hub`, 지역 **Seoul (ap-northeast-2)**, 요금제 확인.
2. 만든 뒤 C비서에게 알려 주시면 아래 1~3을 원문을 보여 드리고 승인받아 진행합니다.

## 1. DB (새 프로젝트 SQL Editor) — 승인 후

1. `supabase/migrations/0001_core.sql` → `0002_org.sql` → `0003_people.sql` 순서로 실행(두 번 실행해도 안전).
2. 운영 설정(공개 저장소에 적지 않는 값):
   ```sql
   insert into core.settings (key, value) values
     ('owner_emails', '["원장 구글 계정"]'::jsonb),
     ('google_client_id', '"<구글 클라이언트 ID>"'::jsonb),
     ('allowed_origins', '["https://ai-aca.github.io"]'::jsonb)
   on conflict (key) do update set value = excluded.value, updated_at = now();
   ```

## 2. 서버 함수 `api` (새 프로젝트) — 승인 후

- 폴더 `supabase/functions/api` 전체를 함수 이름 `api` 로 배포. Verify JWT 켬.
- 프로젝트 Secrets 추가 없음(자동 값 `SUPABASE_DB_URL` 만 사용).

## 3. GitHub 변수 바꾸기

Settings → Secrets and variables → Actions → Variables
- `WHUB_API_URL` = `https://<새 프로젝트 주소>.supabase.co/functions/v1/api`
- `WHUB_SUPABASE_PUBLISHABLE_KEY` = 새 프로젝트의 publishable key

v2 브랜치를 main 에 합치면 검사 통과 후 https://ai-aca.github.io/w-hub/ 에 자동 배포됩니다.

## 4. 배포 후 확인

- 원장 계정 로그인 → 와이즈만/연세국제 전환, 관리 메뉴.
- 다른 계정 로그인 → 승인 대기 → 원장이 영역·센터 권한 지정 → 그 영역만 보이는지.

## 5. 정리(나중에, 승인 후)

School Record 프로젝트에 예전에 넣었던 `core` 스키마·`platform` 함수는 새 프로젝트가 돌아간 뒤 지웁니다. 기존 데이터와는 무관합니다.
