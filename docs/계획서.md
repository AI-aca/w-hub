# 31. W-HUB 최종 계획서 — 새 Supabase · 통합 구조 · 기존 DB 복사 재정리 (2026-11-20)

> **원장님 지시 그대로**
> 1. W-HUB는 **완전히 새로운 사이트(새 GitHub 저장소) + 완전히 새로운 Supabase 프로젝트**다.
> 2. **기존 DB는 반드시 보존한다.** 기존 Supabase(School Record·2027SCI·YSIE)와 연세 구글 시트·드라이브는 읽기만 하고 아무것도 바꾸지 않는다.
> 3. 기존 DB의 데이터는 **복사해서 새 Supabase로 가져오되, 통합 화면에 맞는 새 구조로 재정리**한다. 옛 표 모양을 그대로 옮기지 않는다.
> 4. GAS·구글 드라이브·시트·문서에 저장하는 일은 하나도 없다. 전부 Supabase.
> 5. 와이즈만 학생과 연세국제 학생은 섞지 않는다.
>
> 이 문서가 기준이다. 문서 25~30에서 이와 다른 내용(기존 School Record 프로젝트에 core를 추가해 옛 표를 직접 쓰는 방식, 옛 사이트 탭을 그대로 옮기는 방식)은 **모두 폐기**한다.
> 표기: **[근거: 파일]** 소스에서 확인한 사실 · **[판단]** C비서 설계 결정 · **[확인 필요]** 원장님 답 필요(답 없으면 기본값)
> 이 문서를 바꿀 때는 맨 끝 '변경 기록'에 적는다. 적지 않은 변경은 무효다.

- 메뉴를 **옛 사이트 이름이 아니라 하는 일(학생·성적·수업·입시·분석·일정)**로 나눈다.
- 같은 종류의 일은 한 화면 틀에서 한다: 모의고사 점수·내신 점수·주말반 테스트·온라인 진단 점수는 모두 **성적** 메뉴의 같은 입력표·같은 결과표·같은 성적표 장치로 다룬다.
- 학생 이름은 어디서 눌러도 그 학생 화면으로 간다. 학생 화면에 그 작업공간의 모든 기록이 모인다.
- 기록 하나는 한 곳에만 입력한다. 다른 화면은 가져다 보여 준다(예: 주말반 평가의 모의 점수 = 성적 메뉴의 모의고사 점수).

## 3-2. 뎁스

```
W-HUB (주소 하나, 구글 로그인 한 번)
│
├─ 1뎁스  작업공간: [와이즈만 ▾] [연세국제]   (두 곳 권한자만 바꾸는 버튼이 보임)
│
├─ 와이즈만 — 상단 메뉴(2뎁스)
│   ├─ 홈        오늘 할 일·입력 누락·다가오는 일정·최근 성적
│   ├─ 학생      명부 → 학생 한 명(성적 추이·내신·모의·주말반·입시 서류 전부)
│   ├─ 성적      종류[모의고사 | 내신 성적 | 주말반 테스트] → 학년도·시험 → 탭(설정·입력·결과·순위·성적표·추이·통계·우수자)
│   ├─ 수업      주말반: 과정·학기 → 학기 운영·시간표·진도·반편성·출결·과제·평가·집중관리·문서
│   ├─ 입시      과학고·영재학교: 학생 → 생기부 진단·자소서·채점 근거·예상질문 / 입학요강·기출·합격 사례
│   ├─ 분석      학교 시험 문항 분석(수학·과학): 학교 → 시험 → 문항 입력·리포트 / 출제 통계
│   └─ 일정      통합 달력(주말반 회차·모의 시행일·내신 시험 기간·입시 일정·업무)
│
├─ 연세국제 — 상단 메뉴(2뎁스)
│   ├─ 홈
│   ├─ 학생      연세국제 학생만
│   ├─ 성적      종류[온라인 진단 | 내신 성적] → 시험 → 탭
│   ├─ 입시      외고·국제고: 학생 → 자소서·생기부(160점)·공통과제·예상질문 / 입학요강
│   ├─ 분석      학교 시험 문항 분석(영어)
│   ├─ 문제은행  온라인 진단 문항·묶음·이미지·오디오·시험 구성
│   └─ 일정
│
└─ 관리(원장님)  계정·권한 · 센터·학교·강사 · AI 지시문 · 로그 · 설정 · 옮겨 오기 현황
```

3뎁스 공통 화면 틀: **위 상단 메뉴 → 왼쪽 사이드바(① 범위 ② 대상 목록 또는 화면 메뉴 ③ 하단 버튼) → 오른쪽 작업 영역(머리줄 + 탭)**.

## 3-3. 통합으로 새로 생기는 연결 [판단]

| 연결 | 화면에서 보이는 것 |
|---|---|
| 학생 ↔ 모든 기록 | 학생 화면 하나에 모의·내신·주말반·온라인 진단 점수 추이, 생기부 진단, 자소서 진행이 시간순으로 |
| 모의고사 ↔ 주말반 | 주말반 평가·1지망 판단이 모의 점수·커트라인을 자동 사용(두 번 입력 없음) |
| 내신 성적 ↔ 문항 분석 | 같은 학교·학년·학기·시험이면 성적 화면에 [이 시험 문항 리포트], 분석 화면에 [우리 학생 점수 분포] |
| 강사 ↔ 모든 기록 | 강사 명부 하나: 주말반 담당, 내신 담당자, 입력자 기록이 같은 사람 |
| 일정 ↔ 모든 메뉴 | 주말반 회차·모의 시행일·내신 시험 기간이 한 달력 |
| 출력 | 성적표·문항 리포트·진단지·주말반 리포트·안내장·명예의 전당이 같은 출력 장치, 학생 화면에서도 발급 |
| AI | 생기부 진단·자소서 첨삭·존칭/오타 분석·온라인 진단 코멘트가 같은 AI 장치, 지시문은 관리 화면 한 곳 |

# 4장. 통합 데이터 구조 (새 Supabase 프로젝트)

> 모든 표: RLS 켬, 브라우저 직접 접근 없음(서버 함수만), 작업공간 표에는 `workspace_id` 필수, `created_at/by · updated_at/by`, 지우기는 `deleted_at`(되살리기 가능). 기록 표(`*_log`)로 변경 이력 보관.

## 4-1. core — 계정·권한·운영

`workspaces(weiz, yonsei)`, `users(email, name, is_owner, status, last_login)`, `memberships(email, workspace_id, area, role owner/admin/editor/viewer, center_ids[])`, `sessions`, `audit_log`, `login_fails`, `settings`, `jobs(긴 작업)`, `presence(함께 보는 중)`, `migration_runs(옮겨 오기 실행 기록: 출처·대상·행 수·해시·결과)`

## 4-2. org — 센터·학교·강사

- `centers(id, workspace_id, name, sort, active)` — 와이즈만 청라·송도·한강(김포)·산본·배곧(시흥), 연세국제 세종 [근거: naesin.regions, 문서 14]
- `schools(id, workspace_id, center_id, name, level 중/고, active, sort)` — 내신 학교 목록(센터별) 기준 [근거: naesin.schools]
- `staff(id, workspace_id, name, email→core.users, phone, subjects[], roles[], active)` — 주말반 강사·내신 담당자·자소서 지도 교사를 한 명부로

## 4-3. people — 학생

- `students(id, workspace_id, name, name_no(동명이인 번호), center_id, school_id 또는 school_name, entry_year(중1 입학 연도), student_phone, parent_phone, memo, status)`
- `student_aliases(student_id, source, source_key)` — 옛 DB의 학생 표시(모의 jsonb id, 내신 이름+번호, 생기부 uuid, 2027SCI student_link …)를 기억해 둠. 옮겨 오기 재실행·대조에 씀
- `merge_queue` — 옮겨 오기 때 같은 학생인지 애매한 경우(동명이인·학교 불일치) 원장님 확인 대기
- `student_access(student_id, purpose 자소서/응시, token_hash, expires_at)` — 학생용 링크(입시철 이후)

## 4-4. assess — 시험·응시·점수 (모의·내신 성적·주말반 테스트·온라인 진단을 한 구조로)

```
assessments   id, workspace_id, kind('mock'|'naesin'|'weekly'|'diag'), title, school_year(학년도), round(차수),
              term(학기)·period(중간/기말), subject, school_id, grade, date, class_session_id(주말반 회차),
              config jsonb(모의: 환산 비율·커트라인·평균 규칙 / 진단: 시험 구성), status
sections      assessment_id, key(수학·과학 / 영역 / Grammar…), max, sort
items         assessment_id, section_id, no('1','1-1'), area, max, sort, bank_question_id(진단)
attempts      id, assessment_id, student_id, center_id, grade_at, status('정상'|'미응시'|'특강신청'|'휴회'…),
              total, achievement(A~E), rank_grade, teacher_staff_id, memo, ver
item_scores   attempt_id, item_id, score, answer(진단 답), ver
attempt_log   변경 기록(누가·언제·칸·이전→이후) — 기록 창·되돌리기
cutoffs       assessment_id, school_name, group('서울·경기·한과영' 등), math, sci, total
```

- 모의: 한 차수 = assessment 1개, 학생 = attempt, 문항 점수 = item_scores [근거: mock.exams config·students(m[], s[])]
- 내신 성적: 학교·학년·학기·시험·과목 = assessment, 학생 점수 = attempt.total [근거: naesin.results]
- 주말반 테스트: 회차·반·과목 위클리테스트 = assessment(kind weekly)
- 온라인 진단: 시험 = assessment, 응시 = attempt, 문항별 답 = item_scores [근거: 연세 학생DB 32열]
- **계산(환산·석차·백분위·영역 합계·성취 범위)은 서버·화면이 같이 쓰는 계산 파일 하나**

## 4-7. admission — 입시 서류 (과학고·영재학교 = 와이즈만, 외고·국제고 = 연세국제)

# 6장. 옮겨 오기(복사) 방법과 전환

## 6-1. 방법 [판단]

1. **읽기**: 기존 프로젝트는 원장님이 로그인한 브라우저의 SQL 편집기에서 **select 문만** 실행해 결과를 파일로 받는다(쓰기 문은 도구가 막음). 저장소 파일은 내려받기. 연세 시트는 원장님이 엑셀로 내려받아 올리시고, 드라이브 폴더는 압축해 올리신다 [확인 필요 Q-01].
2. **변환**: 옮겨 오기 도구(`tools/migrate/`, 저장소에 코드만, 데이터는 넣지 않음)가 5장 대응표대로 새 구조로 바꾼다. 같은 학생 판단 규칙: 이름+센터+입학 연도(+학교) 일치 1명이면 합침, 애매하면 `merge_queue`.
3. **넣기**: 새 프로젝트에 넣는다. `core.migration_runs`에 출처·행 수·해시 기록.
4. **대조**: 출처와 새 표의 행 수·점수 합계·무작위 20건·파일 수·크기 비교. 모의 성적표·내신 리포트·생기부 진단지를 옛 사이트와 W-HUB에서 같은 학생으로 만들어 숫자 대조. 하나라도 다르면 전환 안 함(INV-04).
5. **다시 하기 가능**: 같은 도구를 여러 번 돌려도 결과가 같다(시험 복사 → 전환일 최종 복사).
6. **도구 구조(11-24 만듦)**: 작업 하나 = SQL 세 조각(`extract` 원본 읽기 → `{rows, check}`, `load` 넣기, `checkTarget` 대조값). `tools/migrate/run.ts` 가 같은 SQL 을 두 길로 실행한다.
   - SQL 편집기 길: `extract-sql` 을 원본 편집기에서 실행(읽기 전용) → 결과 JSON 을 `target-sql` 로 감싸 W-HUB 편집기에서 실행. 기본은 시험 실행(rollback), `--apply` 일 때만 반영.
   - 직접 길: `run`(두 DB 주소) — 로컬 시험·CI 용. 원본은 read only 트랜잭션.
   - W-HUB 쪽은 한 트랜잭션: 넣기 → 대조(다르면 예외로 전부 되돌림) → `core.migration_runs` 기록.
   - 첫 작업 `mock_users`(모의고사 승인 계정 → 계정·성적·모의고사 권한). 11-24 원장님 승인으로 22명 반영(원장 3명 제외).

## 6-2. 전환 [판단]

- 영역마다 **전환일**을 정한다. 전날까지 옛 사이트 사용 → 전환일 아침 마지막 복사·대조 → 그때부터 W-HUB에만 입력. 옛 사이트와 옛 DB는 그대로 남아 언제든 열어 볼 수 있다(보존).
- 전환 전에는 W-HUB에 '시험 복사본'으로 미리 써 보고 확인.
- 학생이 쓰는 화면(과학고·외고 자소서, 연세 응시)이 있는 영역은 W-HUB 학생용 페이지를 함께 만들어 같은 날 전환하고 새 링크를 준다. 날짜는 원장님이 정한다(입시철) [확인 필요 Q-02].
