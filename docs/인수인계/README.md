## 지금까지의 배포 방식 (claude.ai Cowork 에서 일할 때)
- DB: Supabase 대시보드 SQL 편집기에서 실행 → 표·권한·행 수 확인 쿼리로 검증. 추가(새 칸·새 표)를 먼저, 옛 칸 지우기는 서버 함수 배포 뒤.
- 서버 함수: 위 esbuild 명령으로 묶은 결과의 sha256 을 기록하고, 대시보드 편집기 내용이 직전 배포 sha 와 같은지 확인한 뒤 교체 → 'Deploy updates'.
- 화면: 바뀐 파일을 원장님 PC 폴더 `입시 플랫폼\W-HUB 올리기\whub_v2\...` 에 넣고(+ `commit_message.txt`, `ci-deploy.yml.new`), 다시 읽어 같은지 대조 → 원장님이 `W-HUB_upload.bat` 실행(깨끗한 clone 에 whub_v2 를 미러 복사 후 push) → GitHub 파일 해시 전체 대조, Actions 결과, 실화면 확인.
- 배포 뒤 확인하지 못한 것은 반드시 보고에 적는다.
