# 38. 남은 작업 계획 재확인 — 연세 온라인 진단·블로그 GAS→Supabase 포함 (2026-11-24)

- 과학고 자료는 원장님이 YONSEIIE 의 `science` 칸으로 옮김 → 입시(과학고) 복사 출처가 YONSEIIE 로 바뀜.

## 1. GAS → Supabase 로 바꿀 두 곳

### 1-1. 연세 온라인 진단 (운영 중)
- 지금: GitHub `YONSEI`(화면 690KB) + GAS(`API script.gs`, 요청 27종) + 구글 시트(문제은행·학생 결과) + 드라이브(이미지·오디오·로고·백업 폴더).
- 바꾸는 방식:
  - 시트 → Supabase 표: 문항·묶음(문제은행), 시험·응시·문항별 답·점수(성적 › 온라인 진단), 학생(연세국제 학생 명부), AI 코멘트.
  - 드라이브 파일 → Supabase 저장소(`bank-media`). 드라이브 폴더 구조는 표의 '분류' 칸으로.
  - GAS 요청 27종 → W-HUB 서버 기능으로 하나씩 대응. 대응표는 feature-map 에 이미 들어 있음.
  - Gemini 호출 → 서버 함수에서만(키는 비밀 저장소).
  - 학생 응시 화면 → W-HUB 학생용 페이지. 원장님이 정한 날 전환.
- **옛 자료 읽기 [판단·변경]:** 이 대화에 구글 드라이브·시트 연결 도구가 있다. 원장님 허락을 받아 시트·드라이브를 **읽기만** 해서 복사한다. 그러면 원장님이 엑셀·압축을 내려받아 올리는 수고가 없다(문서 31 Q-01 기본값 변경). 안 되는 파일만 수동.
- 전환 조건: 문항 수·응시 수·점수 합계·미디어 파일 수/크기가 원본과 같을 것. 옛 GAS 사이트는 그대로 둠.

### 1-2. 블로그 자동화 (미완성, 운영 안 함)
- 지금(원장님 폴더, 7월 이후 멈춤):
  - GAS `Code.gs` 107KB + 화면 `index.html` 168KB + `js/`.
  - AI 글 생성 + 이미지 생성(DALL-E, 학원 배색 규칙), 모드 2개(교육정보 칼럼 / 학원 안내).
  - 결과물을 드라이브(센터별 폴더)·구글 문서·시트(설정·이력)에 저장.
- **결정 [판단]:** 미완성이라 '옮기기'가 아니라 **W-HUB 안에서 새로 완성**한다. 옛 코드는 기능·지시문(AI PROMPTS, 배색·그림 규칙)만 참고하고, 옮겨 올 운영 자료는 없음(있으면 이력만).
- 구조:
  - 글·이미지·발행 상태 → Supabase 표(`blog.posts`, `blog.images`, 센터별).
  - 이미지 파일 → 저장소.
  - 지시문 → `ai.prompts`(생기부·자소서 지시문과 같은 곳에서 관리).
  - 글·그림 생성 → 서버 함수(긴 작업은 '작업 진행' 장치로, 창 닫아도 계속).
  - 메뉴: 와이즈만·연세국제 각각 '블로그'(이름은 원장님이 나중에 정함).
- 시작 전에 원장님께 "어디까지 되면 완성인지"를 화면 시안으로 먼저 확인받는다. 완성 기준이 정해지지 않은 채 만들지 않음.
- 비밀값 주의: 블로그 규칙 문서에 평문 비밀번호·키가 있다. 옮겨 적지 않고, 새 비밀 저장소에 원장님이 직접 넣음.

## 2. 남은 단계 (순서 확정)

| 단계 | 내용 | 원장님이 하실 일 | 완료 조건 |
|---|---|---|---|
| **1 마무리** | w-hub 프로젝트에 표 3개(계정·명부·학생) + 서버 함수 `api` + GitHub 변수 + v2 배포. 모의고사 승인 계정 복사 | SQL 원문 승인, 첫 로그인 | 원장 계정 로그인·권한 화면 동작 |
| **2 마무리** | 2028win 화면 직접 열어 버튼 보강, 연세 화면(690KB) 세부 보강, 옮겨 오기 도구 틀(`tools/migrate`) | — | 기능 목록 확정 |
| 3 | 수업(주말반) + 2028win 복사, 일정 | 시간표·진도 화면 확인 | 목록 100%, 행 수 대조, 전환 |
| 4 | 성적 › 모의고사 복사·전환 | 성적표 숫자 대조 확인 | 성적표 일치 |
| 5 | 성적 › 내신 + 분석(문항) 복사·전환 | 리포트·명예의 전당 확인 | 일치 |
| 6 | 입시(와이즈만): 생기부 진단 + 과학고(출처: YONSEIIE science), 학생용 자소서 페이지, 옛 링크 자동 이동 | 전환 날짜 | 진단지·자소서 대조 |
| 7 | 입시(연세국제): 외고·국제고(출처: YONSEIIE public), 학생용 페이지, 옛 링크 자동 이동 | 전환 날짜 | 대조 |
| 8 | **연세 온라인 진단: GAS·시트·드라이브 → Supabase** (문제은행·성적·학생 응시 페이지) | 구글 읽기 허락, 전환 날짜 | 문항·응시·점수·미디어 대조 |
| 9 | 학생 화면·홈 완성 | 확인 | — |
| **10 (추가)** | **블로그: W-HUB 안에서 새로 완성(GAS 없이)** | 완성 기준 시안 확인, AI 키 입력 | 원장님 확인 |
| 11 | 옛 사이트 정리 판단 | 결정 | 옛 DB는 계속 보존 |

- [판단] 블로그를 맨 뒤(10)에 둔 이유: 운영 중이 아니라 전환 위험이 없고, 운영 중인 7개 기능을 먼저 옮기는 게 선생님들 불편을 먼저 줄인다. 원장님이 블로그를 먼저 원하시면 3단계 앞으로 당길 수 있다. 블로그는 다른 단계와 자료가 겹치지 않아 순서를 바꿔도 문제없음.
- [판단] 연세 온라인 진단을 8단계로 유지: 지금 GAS로 정상 운영 중이고 보안 노출(공개 키로 표 전체)이 없는 구조라 급하지 않음. 다만 학생 응시가 몰리는 시기를 피해 전환일을 정함.
