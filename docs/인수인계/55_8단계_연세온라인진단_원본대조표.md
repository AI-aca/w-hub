원칙(문서 46·47·51 방식): 화면·칸만 따라 하지 않는다. 값마다 원본 코드에서 **어느 화면 · 누가 · 무엇 단위 · 특별한 경우**까지 따라간 뒤 코드를 짠다. 이 문서는 **코드를 짜기 전의 대조표**이며, 코드·DB·feature-map·YONSEI 저장소는 건드리지 않았다.

**가장 중요한 구조 사실 3개**
1. **서버에 로그인이 없다.** 관리자 코드·마스터 코드는 화면에서만 확인하고(`verifyAuth` L3595), GAS 는 누가 불러도 처리한다. 그래서 학생 이름·점수 조회, 시험 삭제·초기화, Gemini 호출이 주소만 알면 가능하다(§13). W-HUB 이전의 가장 큰 이유.
2. **'시험지(카테고리)' 하나 = 드라이브 폴더 하나 = 문항 시트 하나 + 학생 시트 하나.** 학생 시트는 시험지별이고 **학생ID 가 같으면 덮어쓴다**(`gs L268~L288`). 같은 학생이 같은 시험지를 다시 봐도 ID 가 응시 때마다 새로 만들어지므로(C-01) 실제로는 매번 새 줄이 생긴다. 덮어쓰기는 채점 확정·수동 수정·학급 변경 때 같은 ID 줄을 고치는 데 쓰인다.
3. **응시 화면은 로그인도 명단도 없다.** 학생이 시험지·이름·학년·응시일·시험 시간을 직접 고른다(`renderStudentLogin` L14237). 채점은 제출 때 하지 않고, 선생님이 '🤖 AI 채점'을 눌러 브라우저에서 계산한 뒤 '확인'으로 저장한다(`runAIGradeAndVerify` L7810, `confirmAIGrade` L7982).

## 7. 시트·드라이브 구조 (코드로 읽은 것) → W-HUB 표·Storage 대응 (초안)

W-HUB 에 `assess`·`bank` 스키마는 **아직 없다**(마이그레이션 0001~0008 에 없음). 계획서 4-4·4-8 과 4·5단계 문서(51·53, PR #3·#7)의 `assess` 초안을 따른다. 번호·적용 순서는 총괄이 배정. 이미 있는 것: `core.workspace_areas` 의 연세국제 `scores_diag`·`bank` 영역(0001), `people.student_access`(`purpose='diag'` 허용, 0003), `people.student_aliases.source='yonsei'` 허용(0003).

### 7-1. 드라이브 폴더 구조 (코드에서 읽음)

```
[루트 폴더]  (script.js L4·L2995 `mainServerLink`, 폴더 ID 는 코드에 있음 — 이 문서에는 적지 않음)

├─ academy_logo.png · academy_banner.png   (LOGO_SAVE)
├─ 백업/                               (삭제한 시험지 폴더가 `_백업_yyyyMMdd_HHmmss` 이름으로 이동)
├─ System_Assets/                      (옛 구조의 흔적: LIST_FOLDERS 가 건너뜀 — 있는지 G-01)
└─ {A|B}_{시험지 이름}/                (시험지마다 하나. A=레벨 테스트지, B=기타)
```

- 시트를 찾는 방법이 **이름에 '학생DB'·'통합DB' 가 포함된 첫 파일**(`getFilesByType(...)` + `includes`)이라, 폴더에 이름이 겹치는 시트가 있으면 엉뚱한 것을 읽는다(§13 F-04).

## 9. 전환 계획 (초안)

**전제**: 약속 3 — 전환일은 원장님이 정한다. 학생이 쓰는 화면(연세 응시)이라 INV-05 에 따라 **응시가 몰리는 시기를 피해** 정한다. 몰리는 시기는 코드로는 알 수 없고, 학생DB 의 응시일 분포(월별·시험지별)를 구글에서 읽어야 한다(G-05) → 읽은 뒤 이 절에 날짜 후보를 채운다.

1. **준비(전환일 전, 옛 사이트는 그대로)**
   1. 원장님 결정(§11) 확정, 구글 읽기 허락(G-01~G-11).
   2. DB 추가(`bank`·`assess` 진단 칸·`diag_*` 표)와 서버 기능·화면을 W-HUB 에서 완성. 학생용 응시 페이지는 **옛 주소와 다른 새 주소**로 열되 아직 학생에게 알리지 않음.
   3. 이관 리허설을 여러 번(읽기 전용, 다시 돌려도 같은 결과). 대조표(§15)가 모두 통과해야 다음으로.
2. **이관 순서**: ① 설정(시험지 목록·학급·학급 평균·브랜드) → ② **문항**(시험지별 Questions·Bundles; 영역·유형·난이도 값 정규화 결과를 보고) → ③ **미디어**(드라이브 파일 → `bank-media`, 파일 ID 별로 sha256·크기 기록, 주소 재작성 표 만들기 — `COPY_EXAM` 이 하는 파일 ID 교체와 같은 일) → ④ **학생(응시자)**(Q-01 결정대로 명부 연결 또는 응시자만) → ⑤ **응시 기록**(학생 줄 → attempts·item_scores·comments, 20명 단위). 앞 단계가 통과해야 다음 단계를 한다.
3. **전환일**: ① 아침 마지막 복사(전환일 이후 새로 생긴 응시·채점·학급 변경이 빠지지 않게 증분: `legacy_code` 로 새 줄만, 바뀐 줄은 `총점·AI 코멘트` 변경 여부 비교) ② 대조 통과 확인 ③ 원장님이 새 응시 링크를 학생에게 배포 ④ 옛 응시 주소는 **그대로 두되**(INV-01: 옛 저장소 수정 금지) 안내는 원장님이 별도로(Q-16).
4. **옛 GAS 는 읽기 보존**: 시트·드라이브는 지우지 않고 그대로 둔다(약속 2, INV-02). 전환 뒤 **새 응시가 옛 시트에 쌓이지 않게** 하려면 옛 쪽 설정을 바꿔야 하는데 그것은 옛 시스템 변경이므로 **원장님이 직접·승인 뒤에만**(예: GAS 웹앱 접근 권한을 원장님 본인으로 제한). 그 전에는 옛 시트 증분 복사를 한 번 더 한다.
5. **되돌리기**: 새 DB 는 추가만 했으므로 새 링크 배포를 멈추면 옛 사이트로 즉시 복귀(옛 사이트·시트가 그대로이므로). 전환 뒤 새 쪽에 쌓인 응시는 `source='online'` 으로 남아 있어 필요하면 옛 시트 형식으로 내보낼 수 있게 엑셀 내려받기를 만든다.
6. **작업 전 백업**: 이관 전 옛 시트·드라이브는 구글 쪽에서 '사본'을 원장님이 만들 수 있으면 그것을 기준(읽기 전용)으로. 사본 못 만들면 읽기 전용으로 직접.
7. **응시가 몰리는 시기 피하기**: G-05 의 월별 분포에서 응시가 가장 적은 구간을 후보로. 전환 직전·직후 1주일에는 시험지·문항 수정을 얼리고, 전환일 오전(응시 0건인 시간대)에 최종 복사.
