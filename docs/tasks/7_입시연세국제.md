# 7단계 — 입시(연세국제): 외고·국제고

## 목표
- 옛 외고·국제고 운영 사이트(`AI-aca/YSIE`, 학생이 링크로 직접 씀)의 기능을 W-HUB `입시 › 연세국제` 에 **100%** 옮긴다(feature-map '외고국제고' 93개, 문서 49 의 예정 추가분 포함).
- **6단계(과학고 + 생기부 진단)와 같은 `admission` 표·같은 화면 틀을 쓴다.** 외고만 다른 것(160점 채점·학급·공통과제·지원학교 미정 규칙·메뉴)만 따로 만든다(54번 10절).
- 옛 사이트와 옛 DB 는 전환일까지 그대로 둔다(읽기만). 전환일은 원장님이 정한다.

## 시작 조건 (이 카드는 이게 정해지기 전에 코드를 시작하지 않는다)
1. **6단계의 `admission` migration 과 공통 코드(자소서 편집창·첨삭·이력·학생 링크·AI 장치)가 먼저 들어가 있을 것.** 7단계는 그 위에 칸·표를 '추가'만 한다. 6단계 표에 작업공간 구분 칸(`workspace_id`)이 없는 표가 있으면 총괄이 6단계 쪽에 먼저 반영한다(54번 10-3).
2. 54번 11절의 원장님 결정: 6단계 D-n 과 같은 질문(D-2~D-12·D-15·D-18·D-20·D-21·D-24~D-26)은 6단계 답을 그대로 따른다. 외고만의 질문 E-1~E-14 중 특히 **E-1(160점 별도 엔진), E-5(지원학교 미정 규칙), E-6(2027 공통과제), E-8(센터), E-9(학급 칸 공유), E-10(합불 열)**.
3. 코드 시작 직전에 GitHub `AI-aca/YSIE`(main)를 다시 받아 54번 1절의 HEAD(`be70ef3`)·파일 해시와 비교. 달라졌으면 변경분을 대조표에 먼저 반영. (과학고 `1d077ac` 도 함께 비교해 두 사이트 공통 변경인지 확인.)

### 7-B 서버 함수 (`supabase/functions/api`)
- `areas/admission/` 에서 **6단계 동작을 공유**하고, 외고만 다음을 추가: 학급 필터·반별 인원 집계 · 지원학교 변경 시 상태 재계산(학교 변경·최종제출 해제·실패 시 롤백) · 지원학교 미정 기본 문항·차단 4가지(최종 제출·AI 도움받기·체크리스트·자소서 예상질문) · 공통과제(설정 CRUD·학년도 규칙·학생 답 저장·PDF) · 학교 단위 글자 수 기준(공백 제외) · 합불 2열 · 외고 생기부 채점(160점).
- `lib/` 순수 계산 모듈(단위 시험 가능): **160점 채점**(`fillMissingGrades`·영어 점수·출결 감점·동점자 8칸·경고) · 외고 점수 근거 카드 4장 · 생기부 점수 정렬 키 · `hasCommonAssignmentForYear` · 반별 인원 집계. 6단계 모듈(글자 수·선생님 수정 횟수·합불 연쇄·자소서 상태)은 재사용하되 외고 규칙(미정 꼬리표)을 옵션으로.
- AI 호출(Gemini)은 서버에서만, 키는 비밀 저장소. 오래 걸리는 일(파싱·채점·총평·예상질문)은 기존 `core.jobs` 작업 진행 장치.

### 7-C 화면 (`web/src/areas/admission/`)
- 입시 › 연세국제: 학생 목록(필터: 검색·지원학교·학년도·학급, 반별 인원 한 줄, 합불 2열) → 학생 탭(생기부 · 자소서 · 과제·예상질문) / 입학요강 / 설정(학교별 문항·공통과제·문자·백업) / 사용법. 기출문제·합격 사례·단계 진단지는 만들지 않음(E-12).
- **자소서 편집창은 6단계 컴포넌트 재사용**: 외고 차이는 설정으로(공백 제외 학교·지원학교 미정 기본 문항·미정 차단 안내 문구).

- 과제 및 예상질문: 공통과제 연습(학생 입력·교사 확인) · 생기부·자소서 기반 예상질문. 외고용 AI 체크리스트 화면(4범주·13항목).
- 학생용 페이지(링크로 열림): 자기소개서 · 과제 및 예상질문 연습 · 입학요강 · 사용안내 **4개만**. 6단계 학생용 진입점을 공유하고 메뉴만 작업공간별로.

- **전환일 직전 재실행**(외고 자료는 11-28 에도 바뀌고 있음).
- 개인정보가 든 백업·내보내기 파일은 저장소에 넣거나 공유하지 않는다.
