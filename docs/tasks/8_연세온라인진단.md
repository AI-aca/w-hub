## 시작 조건 (먼저 끝나 있어야 하는 것)
1. **원장님 결정**(55번 문서 §11) 중 개발을 막는 것: Q-01(응시자 = 명부 학생/지원자) · Q-02(응시 링크 방식) · Q-03(채점 흐름) · Q-14(권한). 나머지는 권장값으로 시작해도 되고 결과를 보고한다.
2. **구글 읽기 허락과 읽기**(55번 §12 G-01~G-11): 문항·학생 줄·미디어 수, 값의 모양을 읽어 55번 §7·§15 를 실제 값으로 채운 뒤 이관 작업을 시작한다. 구글 연결 도구로 오디오·이미지 파일을 받을 수 있는지도 먼저 시험한다(안 되면 원장님과 방법 상의). 설정 시트의 코드·키 값은 읽지 않는다.
3. **4단계(모의고사)의 `assess` 스키마가 main 에 합쳐진 뒤** `assess` 를 건드리는 작업(8-B 이후)을 시작한다(같은 DB 를 두 에이전트가 동시에 고치지 않음). 문제은행(8-A)은 `assess` 와 독립이라 먼저 시작해도 된다. 4단계 착수 전에 총괄에 요청: `assess.attempts.student_id` 를 **null 허용**으로(Q-01 결정 전까지).
4. 원본 새로 받기: GitHub `AI-aca/YONSEI` master 최신본(대조표 기준 HEAD `f994f8cd`, `index.html`·`script.js`·`style.css` blob 해시 `8dafaa9a…`·`958c6d43…`·`5d63f97e…`, `API script.gs` `8bb82a2f…`)을 다시 대조하고, 바뀌었으면 대조표를 먼저 고친다. **배포된 GAS 가 저장소 사본과 같은지는 원장님이 GAS 편집기에서 확인**(G-11).
5. 마이그레이션 번호·서버 함수 번들 기록은 **총괄이 배정**한다(이 카드에서 정하지 않음).

## 할 일 (순서대로)
1. **계산 파일 하나(진단 전용)**: 채점 1단계(`객관형` 정렬 비교·주관형 키워드·괄호 확장·`PN_MAP`)·영역·난이도 합계·정답률·상위 %·성취 7단계·학급 평균 편차·학급 추천(미달반 70% 규칙)을 서버·화면이 같이 쓰는 순수 함수로(`shared/calc/diag.ts`, 모의 `calc` 와 합치지 않음, 55번 §8). **원본 함수를 줄 번호로 그대로 떼어 무작위 자료와 비교하는 시험(차이 0)을 먼저** 만든다(55번 §14-1: `script.js L7829~L7877`·`L4870~L5028`. 백분위·편차 계산부는 DOM 에서 떼어내는 작업부터). 키워드 채점의 부분 문자열 오채점(Q-04)은 결정대로 하고, 결정 전에는 **원본 동작 그대로**.
2. **DB(추가만)**: ① `bank`(`papers`·`questions`·`bundles`·`media`) ② `assess` 의 진단용 칸·표(`attempts` 칸 추가, `item_scores.answer·correct·ai_graded·feedback`, `attempt_comments`, `diag_class_avg`, `diag_classes`) ③ Storage 버킷 `bank-media`(비공개) ④ `ai.prompts` 진단용 키. 55번 §7-3 이 초안. 기존 표·칸은 건드리지 않는다. 모든 변경은 두 번 실행해도 안전하게, 작업 전 백업, 되돌릴 수 있게. `core.workspace_areas` 의 연세국제 `scores_diag`·`bank` 를 완성 뒤 `ready` 로.
3. **서버 기능**(권한은 Q-14 결정대로): 문제은행 — `paperList·paperGet·paperSave(문항 단위+순서)·paperCopy·paperDelete·paperReset·questionSave·mediaUpload·brandSave`. 응시(학생용, 로그인 없음) — `examLoad`(정답·모범답안 제외)·`examSave`(임시 저장)·`examSubmit`·`audioPlay`(서버가 횟수 기록). 채점·성적 — `diagGrade`(서버 작업, 진행 표시)·`diagGradeConfirm`·`attemptList·attemptGet·attemptDelete(되살리기 가능)·attemptSetClass·attemptCommentSave`·수동 입력(칸 단위 저장)·`diagClassAvgList/Save`·`diagStats`. AI — `aiRun`(Gemini 는 서버 함수에서만, 키는 비밀 저장소에 원장님이 직접 입력, 지시문은 `ai.prompts`에 **원문 그대로**). **새 검사**: 모든 기능에서 작업공간·영역 권한을 서버가 확인, 학생용 기능은 응시 링크·코드·시도 횟수 제한, 입력자 = 로그인 계정. `feature-map.json` 의 actions 와 연세 항목 status 를 고친다(`GET_AUDIO_B64` 추가, `to` 세분).
4. **화면**: 문제은행 메뉴(시험지 목록·만들기·복사·삭제 / 문항 목록·등록기·수정 / 미디어 올리기) — 등록기의 서식 막대·붙여넣기 파서·묶음 연결·끌어서 순서·변경 표시·나가기 경고까지(S-19, B-23~B-30·B-36·B-37). 성적 › 온라인 진단(채점 / 학생 DB / 성적표 / 수동 입력 / 학급 평균 / 통계 — S-07~S-14). 학생용 응시 페이지(S-02~S-05, 옛 UI 문구 그대로, D-14). 공통 부품(입력표·확인 창·이미지 저장·출력·사이드바)은 4단계/3-2A 것을 재사용. 외부 CDN 라이브러리(Tailwind·Chart.js·flatpickr)와 글꼴은 **저장소에 포함**(5단계 Q-17 방식). 작업 중 창 닫기 경고·저장 중 경고는 공통 부품 그대로.
5. **옮겨 오기**: `tools/migrate/jobs/diag_bank.ts`(설정·문항·묶음) → 미디어 이관(`bank-media`, 파일마다 sha256·크기, 주소 재작성 표) → `diag_attempts.ts`(응시자·응시 기록, **20명 단위**, 학생마다 문항별상세 지문). 읽기 전용, 서버끼리, 다시 돌려도 같은 결과(`legacy_id`·`legacy_code`·`legacy_drive_id`). 학생 연결은 55번 Q-01 결정과 `merge_queue`. 개인정보(이름·점수)는 로그·문서·커밋에 남기지 않는다.
6. **전환 준비(8-E)**: 55번 §9 순서(설정 → 문항 → 미디어 → 학생 → 응시 기록, 전환일 아침 증분 복사), 새 응시 링크, 옛 시트 읽기 보존. 전환일은 원장님이 정한다(약속 3, 응시가 적은 구간).
7. 기능 지도 갱신·인수인계 README '지금 상태' 갱신·55번 문서 갱신(실제 값 채우기).

## 필요한 DB 변경 개요 (migration 번호: **총괄이 배정**)
- 새 스키마 `bank`: `papers`(이름·분류 A/B·권장 학년·권장 시간·`legacy_id`·삭제 표시) · `questions`(번호·영역·세부영역·유형·난이도·배점·질문·지문·이미지·보기 jsonb·정답·모범답안·묶음·라벨타입, 유일 `(paper_id, no)`) · `bundles`(제목·지문·이미지·오디오·최대 재생 횟수·연결문항번호 원문) · `media`(종류·저장 위치·MIME·크기·sha256·`legacy_drive_id`·`legacy_url`).
- `assess`(4단계가 만든 것에 추가만): `attempts` 에 `name_at`·`grade_at`·`class_name`·`test_date`·`status`(`in_progress/submitted/graded`)·`score_breakdown jsonb`·`legacy_code`·`source`·`started_at`·`time_limit_min`·`audio_plays jsonb`, `item_scores` 에 `answer`·`correct`·`ai_graded`·`feedback`(4·5단계가 이미 계획한 칸은 같은 이름으로), 새 표 `attempt_comments`·`diag_class_avg`·`diag_classes`. `student_id` null 허용(Q-01).
- Storage `bank-media`(비공개, 서버가 짧은 시간 유효 주소 발급).
- 권한·RLS: 기존 표와 같은 방식(서버 역할만 읽기·쓰기, 화면용 역할 접근 불가). 학생용 기능은 서버가 응시 링크·코드를 검사하고 문항 자료에서 정답·모범답안을 제외.
- `ai.prompts`: 진단 채점·영역 코멘트·종합 코멘트·문항 보조 지시문(원문 그대로, 버전 관리).
- `people.student_access`(`purpose='diag'`)·`student_aliases.source='yonsei'` 는 0003 에 이미 허용됨(Q-01·Q-02 결정에 따라 사용).
- 옛 칸 정리는 없음(옛 시트·드라이브는 계속 보존).

## 검증 (끝났다고 말하기 전)
- `npm run check` 지적 그대로 따름 → `npm run verify`(타입·구조·서버·화면 시험 + 캡처) → 캡처를 직접 열어 확인.
- 55번 문서 §15: 문항·묶음·미디어(수·크기·sha256)·응시 줄·점수 합·학생마다 지문 대조, 계산 차이 0, 작업공간 격리, 정답 미노출·서버 강제(시간·듣기) 시험, 30명 동시 제출 시험, 화면 대조(옛 사이트와 같은 값·같은 문구).
- 원장님께는 캡처와 쉬운 말 요약: 바뀐 것 · 확인한 것 · **확인 못 한 것**.

## 완료 조건
- 옛 연세 사이트의 예정 기능(feature-map 연세 191개)이 W-HUB 에서 모두 되거나, 55번 문서에 '일부러 다름/만들지 않음'과 이유가 적혀 있고 원장님이 확인함.
- 문항·응시·점수·미디어 대조 통과(INV-04). 하나라도 다르면 전환하지 않음.
- 전환일은 원장님이 정한다(약속 3). 전환일에 시험·응시 기록을 마지막으로 한 번 더 복사하고, 그날부터 옛 사이트는 보기만(읽기 보존).
